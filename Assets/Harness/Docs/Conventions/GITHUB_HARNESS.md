# GitHub 하네스

## 브랜치 전략

- 전략: Git-Flow
- `main`: 배포 가능한 안정 버전
- `develop`: 개발 통합 브랜치
- `feature/*`: 기능 개발
- `fix/*`: 일반 버그 수정
- `hotfix/*`: 긴급 수정
- `refactor/*`: 구조 개선
- `test/*`: 테스트 작업
- `docs/*`: 문서 작업
- `release/*`: 출시 준비

## 커밋 메시지 규칙

- 커밋 메시지는 한글로 작성한다.
- 기본 형식: `타입: 한글 설명 #이슈번호`
- 예시:
  - `feat: 플레이어 반동 추가 #124`
  - `fix: 좀비 공격 판정 오류 수정 #208`
  - `docs: 하네스 문서 정리 #301`

## 커밋 타입

- `feat`: 새로운 기능 추가
- `fix`: 버그 수정
- `docs`: 문서 수정
- `test`: 테스트 코드 또는 테스트 작업
- `refactor`: 리팩토링
- `build`: 빌드 파일 수정
- `rename`: 파일 또는 폴더 이름만 수정한 경우
- `remove`: 파일 삭제만 수행한 경우

## 이슈 규칙

- 이슈 제목은 대괄호 타입으로 시작한다.
- 타입 첫 글자는 대문자로 작성한다.
- 예시:
  - `[Feat] 플레이어 반동 추가`
  - `[Fix] 웨이브 종료 조건 수정`
  - `[Docs] 하네스 문서 보강`

## 작업 흐름

1. `develop`에서 작업 브랜치를 만든다.
2. 기능 단위로 작은 커밋을 남긴다.
3. 이슈 번호를 커밋 메시지에 연결한다.
4. 검증 후 `develop`으로 병합한다.
5. 출시 시점에 `release/*`를 거쳐 `main`으로 반영한다.
