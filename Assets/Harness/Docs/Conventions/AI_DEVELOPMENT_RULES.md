# AI 개발 규칙

## 우선순위

1. 현재 대화의 직접 프롬프트를 가장 우선한다.
2. 그 다음 `Assets/Harness/WORK_ORDER.md`를 따른다.
3. 그 다음 하네스 문서와 프로젝트 구조를 따른다.

## 작업 원칙

1. 관련 파일을 먼저 읽고 수정한다.
2. 로컬 확장 지점으로 해결 가능한 경우 기존 public API를 함부로 바꾸지 않는다.
3. 기능이 정말 여러 경계를 넘지 않는 이상 `Player`, `Weapon`, `Enemy`, `Defense`, `Core`를 한 번에 크게 흔들지 않는다.
4. 기존 매니저나 컨트롤러를 먼저 재사용할 수 있는지 확인한다.
5. 중복 시스템을 새로 만들지 않는다.
6. 검증용 씬이 아직 없으면 `SampleScene` 또는 새 테스트 씬을 기준으로 검증 경로를 먼저 정한다.
7. 항상 빌드 가능한 상태로 작업을 마친다.

## 구현 원칙

1. 임시 구현이 필요해도 지시가 없다면 먼저 동작하는 구현을 만든다.
2. 튜닝 가능성이 높은 값은 설정이나 데이터로 뺀다.
3. 주석과 디버그 노출 문구는 한글을 우선한다.
4. 에디터 코드와 인스펙터에 보이는 필드는 한글을 우선한다.
5. 큰 선언부의 문서화가 필요하면 XML 문서 주석을 사용한다.
6. 일반적인 보조 설명은 기본 주석을 사용한다.

## 작업 기록

1. 작업이 끝나면 `Assets/Harness/Docs/Logs/FILE_CHANGE_LOG.md`를 갱신한다.
2. 어떤 파일을 왜 수정했는지 짧게 남긴다.
3. 사용자가 `메모 작업해`라고 지시하면 `Assets/Harness/WORK_ORDER.md`를 먼저 읽고 그 안의 지시를 실제 작업으로 수행한다.
4. `메모 작업해`를 받았을 때는 `Assets/Harness/WORK_ORDER.md`를 단순 편집하지 말고, 비어 있지 않은 작업 내용을 기준으로 구현을 진행한다.
5. `Assets/Harness/WORK_ORDER.md`는 템플릿 문서로 취급한다.
6. 사용자가 지우라고 명시하지 않는 한 `WORK_ORDER.md`에 메모나 상태 기록을 덧붙이지 않는다.
7. 메모가 필요하면 `Assets/Harness/Docs/Logs/FILE_CHANGE_LOG.md`의 메모 파트에 기록한다.
